# CCC 垃圾债利差 · 见顶 / 见底预警

跟踪 ICE BofA 美国 CCC 及以下高收益债的期权调整利差（FRED: `BAMLH0A3HYC`），只看利差自身的技术形态，
对纳斯达克综合指数给出两种提示：**见顶预警**（信用转坏、股价还在高位）和**见底预警**（信用恐慌开始回落）。

双击 **`更新并打开.command`** 即可：从 FRED 拉最新数据 → 重算 → 打开网页。
首次可能要右键 →「打开」放行一次（macOS 的隔离标记），之后直接双击。
只用 macOS 自带的 `python3` 与 `curl`，**不需要安装任何依赖**；没有 python3 时按提示跑一次 `xcode-select --install`。

> 先读文末「局限」。这套规则是在 2016-10 以来的十年数据上比较后定下的，只有 6 个下跌顶、5 个底部，没有样本外检验。

---

## 规则（2026-10-23 定）

| | 条件 | 冷却 |
|---|---|---|
| ▼ **见顶预警** | 利差**上穿 200 日均线**（前一日在线下、当日在线上），且纳指收盘**距一年最高收盘不到 5%** | 距上一次满足条件不到 63 个交易日的不再报 |
| ▲ **见底预警** | 利差 **20 日内曾到一年里的第 95 分位以上**；当日**跌破 10 日均线且 10 日均线比 3 日前低**；且纳指**距一年最高收盘已跌 10% 以上** | 20 个交易日 |

- 见顶：利差的低点通常比股票的顶早几个月（2021、2022、2024、2026 都是这样），利差站上 200 日线说明信用趋势已转坏，
  这时股价还在高位就是背离。**规则只在上穿那天报一次**；之后利差一直在线上方、纳指仍在高位时，页面会标「背离持续中」。
- 见底：底部附近利差几乎都在一年的 95~100 分位（2018-12、2020-03、2022-06/10、2025-04），所以先要求「到过极值」，
  再用 10 日线确认回落。要求纳指已跌 10% 与见顶要求「在高点 5% 内」对称：没有下跌就谈不上见底。
- **阶段**（只是读数说明，不进信号）：分位 ≥ 95「压力」、≤ 10「自满」，其余按利差在 200 日线上方 / 下方记「走阔」/「平稳」。
- 日历以纳指交易日为准；ICE 利差在美股休市日也有数，每个交易日取当日或之前最近一个值。
- 参数都在 `signals.py` 顶部。

## 历史表现（数据到 2026-10-20，2017-08-09 起两条规则都有读数）

**见顶预警**：亮了 6 次。6 个下跌顶（一年新高、之后 63 日内跌 ≥ 11%）里，亮灯后 126 个交易日内出现的有 **3 个**
（2020-02、2021-11、2024-07，提前 19~33 个交易日）；没抓到 2018-08、2020-09、2024-12。

| | 亮灯后 63 日纳指 | 之后 126 日内最大回撤 |
|---|---|---|
| 见顶预警（6 次） | **−1.4%** | −9.9% |
| 基准：纳指在高点 5% 以内的所有日子 | +2.8% | −9.1% |

**见底预警**：亮了 7 次。5 个底部（前后 63 日最低、比一年高点低 ≥ 15%）里，亮灯落在底前 21 日至底后 42 日内的有 **4 个**
（2018-12、2020-03、2022-06、2025-04）；没抓到 2022-12。

| | 亮灯后 63 日纳指 | 为负的比例 |
|---|---|---|
| 见底预警（7 次） | **+6.5%** | 43% |
| 基准：所有日子 | +4.5% | |
| 基准：纳指已跌 10% 以上的所有日子 | **+6.4%** | |

**见底预警之后的收益和「纳指已经跌了 10%」本身差不多**——它的用处是告诉你信用恐慌在回落、抓到了 4/5 个底，
不是额外的超额收益。2022 年熊市里它连着亮了 4 次（03、05、07、10 月），03-21 那次之后又跌了 23%。

页面上的这些数字每次运行都按最新数据重算。

## 稳健性：相邻参数

见顶（上穿 N 日均线 × 纳指距高点 ≤ x）：

| | ≤ 3% | ≤ 5% | ≤ 8% |
|---|---|---|---|
| MA150 | 9 次 / 抓 4 顶 / 63 日 +5.3% | 9 / 4 / +5.3% | 9 / 4 / +5.6% |
| **MA200** | 6 / 3 / −2.9% | **6 / 3 / −1.4%** | 6 / 3 / +1.1% |
| MA250 | 5 / 3 / −0.8% | 5 / 3 / −0.8% | 5 / 3 / −0.8% |

MA150 多报 3 次、多抓到 1 个顶，但亮灯后 63 日平均 +5.3%，比基准还高，区分力没了；MA200 与 MA250 结论一致。

见底（20 日内曾 ≥ q 分位、跌破 M 日线且该线下行，冷却 20 日）：

| 附加条件 | MA5 | **MA10** | MA20 |
|---|---|---|---|
| 无 | 12 次 / 抓 4 底 / +4.4% | 12 / 4 / +6.0% | 12 / 4 / +4.0% |
| **纳指距高点 ≤ −10%** | 8 / 4 / +4.2% | **7 / 4 / +6.5%** | 6 / 4 / +4.3% |
| 纳指距高点 ≤ −15% | 6 / 4 / +8.4% | 5 / 3 / +10.2% | 3 / 2 / +8.5% |
| 纳指距高点 ≤ −20% | 4 / 2 / +2.4% | 3 / 1 / −2.7% | 2 / 1 / −1.9% |

分位门槛 90 / 95 / 97 差别很小（抓底都是 4/5）。各格之间的差距在几次事件的噪声以内，所以取了中间的整数，没有挑最好看的那格
（−15% 那行 63 日更高，但少抓一个底）。

试过但没用的见顶写法：利差离半年低点走阔 10% / 15% / 20%（只抓 1~2 个顶）、50 日线上穿 200 日线（4 次 / 2 顶）。

## 局限（看信号前先读）

1. **样本很小**：6 个下跌顶、5 个底部。任何一个百分比都只代表几次事件。
2. **规则是看过这段数据才定的**：参数取整数、没有逐个优化，但候选规则是在同一段数据上比较后选的，页面上的统计全是样本内。
   FRED 只给 ICE 系列最近约 3 年，拿不到 2016 年以前的数据做留出检验；手里有更早的 CCC 利差历史，放进 `data/ccc_oas.csv` 就能重算。
3. **见底预警几乎没有超额**（见上表），2022 那类熊市是它的盲区。
4. **见顶预警不是择时信号**：亮了到见顶过去要 19~33 个交易日，6 次里有 3 次之后没出下跌顶；规则只在上穿那天报一次。
5. 之前在 best-weights 里测过：把 CCC 利差的 252 日分位加进红点温度（任一方向、0~50% 权重），都没能改善红点。
   这里是另一种用法——只看利差自身的形态，单独提示——两者不矛盾，但也不要把这里的提示叠加进红点。

## 数据

| 文件 | 内容 |
|---|---|
| `data/ccc_oas.csv` | CCC 利差（%），2016-10-24 起；ICE 日历，含美股休市日 |
| `data/nasdaq.csv` | 纳斯达克综合指数收盘，2016-10-24 起 |

- 来源（按顺序试，第一个成功的为准）：FRED 官方 API（要免费 key，可选）→ FRED 网页下载 `fredgraph.csv`；
  纳指另有 Yahoo `^IXIC` 兜底。CCC 利差只有 FRED 一个免费来源。FRED 上 ICE 系列只给最近约 3 年，
  所以**本地数据只增不减**：下载到的日期覆盖同日的旧值（接住修订），下载里没有的老日期原样保留。
  种子数据（2016-10 ~ 2026-10-20）来自 FRED，早期部分取自 JustHodl 保存的 FRED 历史存档。
- 同一天新旧值相差超过 25% 时整次不并入（多半是下错了序列），页面顶部会提示。
- **版权**：ICE 指数数据注明未经许可不得转载。**GitHub 仓库请设为私有。**

## 本地运行与 GitHub

- **本地**：`data/` 只读，新下载的数据写进 `cache/`（不进 git），产物 `dashboard.html`、`run.log` 也不进 git。
  所以这个文件夹如果是 `git clone` 下来的，双击时会先 `git pull`（拿代码与存档数据的更新），不会和本地数据冲突。
- **GitHub 每日流水线**（`.github/workflows/daily.yml`）：工作日纽约时间 17:00 跑一次（改了代码推上去也会跑；这时 FRED 多半只有前一交易日的数据），
  `python3 update.py --ci` 把新数据写回 `data/`，并往 `信号快照.csv` 追加当天的读数与信号——**只追加、不改写**，
  以后改了规则或数据被修订，当时页面上显示过什么仍有据可查。每次运行的下载结果（每个来源成功与否、失败原因）
  写进 `ci_status.json` 一起提交。也可以在 Actions 页面手动运行。

## 下载不下来怎么办

页面顶部出现黄色的「本次下载失败」时，按下面顺序处理（每个来源的失败原因在 `run.log` 里）：

1. **改用 git clone 的文件夹**（最省事）。GitHub 流水线在美国机房下载，基本不受本地网络影响；
   双击时会先 `git pull` 拿到它更新好的 `data/`，本机连不上 FRED 也能看到最新数据（最多晚一天）。
   ```bash
   cd ~/Desktop/模型 && git clone https://github.com/chaodu211-cell/ccc-spread.git
   ```
   仓库是私有的话，本机要登录过 GitHub（GitHub Desktop，或 `gh auth login`）。
2. **申请 FRED API key**（免费，几分钟）：https://fredaccount.stlouisfed.org/apikeys 注册后生成一个 32 位的 key，
   - 本地：在本文件夹新建 `fred_api_key.txt`，里面只写这一行 key（这个文件不进 git）；
   - GitHub：仓库 Settings → Secrets and variables → Actions → New repository secret，名字 `FRED_API_KEY`。
   FRED 的网页下载对脚本时好时坏（超时、直接断开都见过），API 是给程序用的正门，稳得多。
3. **代理**：浏览器能打开 https://fred.stlouisfed.org 、终端里却下载失败，多半是代理只对浏览器生效。
   脚本会自动读 macOS 的系统代理（日志第一行会显示「系统代理：…」）；用的是不设系统代理的工具时，
   在终端里先 `export https_proxy=http://127.0.0.1:端口` 再运行 `python3 update.py`。

命令行用法：

```bash
python3 update.py             # 下载 + 重算 + 生成 dashboard.html
python3 update.py --offline   # 不下载，只用本地数据重算
python3 test_signals.py       # 自检
```

## 文件

| 文件 | 作用 |
|---|---|
| `更新并打开.command` | **日常用这个**，双击即可 |
| `update.py` | 一条龙：下载 → 重算 → 生成页面（`--ci` 写回 data/ 并追加快照） |
| `fetch.py` | 多来源下载并合并（FRED API → FRED 网页 → Yahoo；curl 优先，退回 urllib，自动走系统代理） |

| `make_page.py` `template.html` | 生成单文件网页（图是页面自己画的，离线也能打开） |
| `test_signals.py` | 计算核心与下载解析的自检 |
| `信号快照.csv` | 每日信号快照（流水线写，首次运行后出现） |
| `ci_status.json` | 流水线最近一次的下载结果与失败原因（流水线写） |
| `fred_api_key.txt` | 可选，自己建，放 FRED API key（不进 git） |
